## 1. 已确认的边界

第三方原始数据先映射到系统字段、类型和单位，再进入标准数据库与数据服务。UI 继续只做既有展示换算：volume 手 → 万手，amount 元 → 亿，小数比例 → 百分数。各来源的原始字段和值另保留为证据，不能混入标准字段。

UI 的 11 行、顺序、颜色、精度、小额阈值、时间、主副图 hover、坐标轴、指标公式与显示矩阵保持既有规范。数据源换用股、千元或百分数，不构成修改 UI 规则的理由。

### 3.1 旧数据迁移约束

1. 从实际旧数据/代码确认每个字段的来源、单位、类型、复权、时段、缺失补零及派生公式，不能仅凭名称判断旧值已经合格。
2. 建立旧版本与 `market-data/v1`、来源契约和价格/时段配置的映射。确认本来就是手/元的合格值可保持数值；原始股数/千元等须按来源映射转换并产生新版本。旧证据与快照保留。
3. 超精度、未知单位、未知时间、复权不兼容、原先缺失被补零且无法恢复的记录隔离或从合格来源重取；不能只改列名、类型或版本标签就完成迁移。
4. 先验证标准存储与服务输出，再发布完整数据集。对比同一标准输入的 UI 结果，保留旧快照以便回退；重放受影响指标与信号，不能继续复用旧输入的检查点。

### 3.2 当前后置事项

以下涉及趋势研究“首期”的安排和待办保留为此前讨论选项；当前不据此排定产品交付，也不要求完成这些细则后才开始原型。下一步取舍以产品探索中的证据为依据。

- 股票与板块首期聚焦日终发现、核查及持续跟踪；盘中观察和账户可交易性检查后置，日终候选成交额门槛仍属于首期。
- 行业首期一级概览、二级发现；后续扩展一级／二级／三级独立候选及分层排名，见[待办 001](../todos/001-pending-p3-multilevel-industry-candidates.md)。价格容差先用固定百分比，后续过渡到 ATR，切换前需明确参数、样本对照与版本规则。
- 平台首期采用前、中、后三段高低价极值比较，摆动高低点识别见[待办 002](../todos/002-pending-p3-swing-point-platform-detection.md)。已确认 20／40／60 根窗口最多跨 30／60／90 个交易日、最多跨越 5 日连续整日停牌、收盘突破至少 1%、原平台首次突破后再复用 20 个交易日及收盘跌破下沿失效；板块各必需指标要求覆盖率 ≥95% 且至少 10 个有效成员。
- 上下沿稳定、抬底幅度及平台宽度阈值按用户要求保留在[待办 003](../todos/003-pending-p2-platform-structure-thresholds.md)，是首期规则的待补齐项；不能因记录待办就跳过平台成立检查。接近上沿容差、独立测试规则、等权组合细则等仍需继续确定。
- 2026-09-18 上一轮访谈按用户要求结束，2026-09-19 继续并确认 Q19～Q28。高度重叠且压力区域近似的滚动平台跨窗口检查是否延续；未知路径暂停确认但不延长期限，固定日终截止后新增发现只补历史研究结果，同一事件不能改用恢复当日再次达标自动触发。迟到历史信号可由用户加入手动观察；修订逐信号标记并立即提示复核，恢复成立不新增信号、不恢复已结束跟踪、不撤销未处理提示，资格失效仍按自动候选原规则结束。归并判据、截止具体时刻与依据、手动观察细则见[需求第 8.5 节](2026-09-09-volume-breakout-five-condition-data-requirements.md#85-本次访谈收尾与保留的未决项)。这些选择尚待验证，当前暂停细则访谈，转为原型探索。
- 尚未指定或实测完整替代来源；可用权限、延迟、历史覆盖和费用不能从统一契约推断。
- ETF、指数的品类配置和 Tick/盘口/交易完整类型须在对应能力启用前分别确定；股票单位不能自动推广。
- 跨源逐字段融合、逐 bar 自动补洞和系统自建复权引擎后置；本期以分数据集供数、同类对照及完整系列切换为准。
- 真实来源的验收记录、数据库压测/恢复、浏览器 UI 对照尚待实施，不能标为已通过。
