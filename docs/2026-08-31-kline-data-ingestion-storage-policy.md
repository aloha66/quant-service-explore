# K线图数据获取、入库与补偿策略（仅 K 线）

> 状态：PostgreSQL 下后续 K 线图数据获取、缓存、入库、补偿、查询与实时交易行情处理的约束基线；本文不提供 DDL、业务代码、数据库迁移、接口或定时任务实现。
>
> 范围：股票、指数、ETF 的 OHLCV K 线、Tick、实时行情，以及直接决定它们历史可解释性的证券、交易日历、股票池和板块成员 PIT（point-in-time）依赖。
>
> 排除项：财报、研报、公告、新闻、资金流、因子等不是本文的 K 线事实数据，不能写入本文定义的 K 线事实表；它们如被使用，只能以各自契约的外部依赖引用出现。

> 更新日期：2026-09-12。字段、单位和类型遵守[统一行情数据契约](2026-09-12-market-data-contract.md)；QMT 调用、本地缓存和原始字段已移至[QMT 接入规范](2026-09-12-qmt-source-adapter-spec.md)。本文只规定通用生命周期，既有 UI 展示规则不变。

## 1. 决策摘要

区分 **来源侧缓存（若有）+ 应用临时缓存 + PostgreSQL 持久事实** 三种生命周期；另保留受保护的原始响应证据。来源可经本地客户端、远程查询或订阅供数，不要求所有来源经过 QMT 缓存。

1. QMT 与其他来源都按能力、来源契约和数据集选择策略准入。每个 K 线数据集首期固定一个已验收主来源，可并存其他来源的标准候选用于比较；不在源故障时静默跨源按时间或字段拼接。
2. 首期持久化全市场前复权 `1d` 日线。分钟事实表只在第一个实际盘中策略池启用；Tick 不建设全市场事实仓。来源选择不能改变基础周期、保留期或已确定的 UI 表现。
3. 标准入库值为统一契约字段：股票 `volume` 为手、`amount` 为人民币元，比例为小数比例。来源字段先映射、换算和校验；保留原始响应、接收时间、来源及复权证据。数据库、服务和 UI 之间不得重复进行渠道单位转换。
4. 研究/图表默认前复权且不伪造填充 bar。算法、锚定基准、时段与快照必须可验证；除权或供应商修订按完整受影响范围刷新并发布新系列，不能只追加新日期。来源参数属于来源契约，不是业务接口参数。
5. 日终异动、正式涨幅榜和默认研究/回测只读取 `quality_status=SEALED` 的 coverage，并固定其事实输入清单。DEGRADED 只能带状态预览或显式降级消费，不能伪装成正式完整结果。
6. 实时交易标的是小范围订阅。行情时间未知、断线或缺口超阈值时进入 STALE_DATA；恢复须验证。行情来源选择与账户/下单通道相互独立。

原始证据、标准候选、已发布事实和 UI 展示值分别管理。来源未通过验收时不因多源设计而自动成为正式可用来源。

## 2. 通用来源能力与采集边界

### 2.1 获取、读取与标准化

适配器按 `source_contract_version` 固定供数入口、权限、返回结构、字段/单位/枚举转换、时间和完成证据，声明实现的 `data_contract_version`。采集流程统一为：确定数据集与来源 → 获取所需范围 → 保存原始证据 → 标准化 → 校验 → 候选 coverage → 发布。来源侧是否需预下载、是否有本地缓存以及如何刷新历史，由适配器实现。

读取空值不能直接解释为停牌或无成交。应结合来源覆盖、请求结果、状态证据分类；只有具备本地缓存的来源才使用 NOT_DOWNLOADED / LOCAL_RANGE_MISSING 等原因，无对应能力时不能捏造缓存状态。历史请求须限定闭合区间，响应中存在实时未完成 bar 时单独标记。

### 2.2 基础周期与派生规划

数据集 `canonical_base_interval` 由实际指标需求决定，来源原生周期和可派生周期由能力登记决定。目标仅需 5m 时可保存已验证原生 5m，或由完整 1m 按登记的派生契约生成；两条路径必须记录各自输入，不能默认数值等价。日/周/月以 1d 为基础，分钟按 1m 或 5m 登记，Tick 使用独立实时契约。

标准周期名称、时间槽、午休和端点规则来自统一契约。QMT 的原生基础下载限制只见其接入规范，不扩展为系统对其他来源的限制。数据源缺少足够基础数据时返回能力/覆盖不足，不把低频值复制为高频 bar。

### 2.3 标准字段与原始证据

正式 K 线字段、目标持久类型、单位、UI 映射以统一契约第 2、3 节为准。`open/high/low/close/volume/amount` 是已标准化数值；`volume` 固定手、`amount` 固定元，不能在同表按来源保存不同单位。原始 `time`、字段拼写、枚举、价格、量额保存在可读取证据中。

结算价、持仓量及渠道专有字段按品类决定是否适用，不能因 QMT 返回就成为所有股票来源的必填项。Tick 累计量、盘口和交易字段使用各自契约，不能代入区间 K 线。

### 2.4 时间、填充与基础事实口径

1. 默认研究/图表系列为 FRONT_ADJUSTED，并绑定复权方法、时段契约和复权快照。不同方法或未复权序列独立登记，不按日期拼接；本期不新增系统复权引擎。
2. 正式事实不得含伪造填充 bar。来源支持关闭填充时必须关闭；不支持时须有可验证的未填充证据，否则不晋升。股票量额须符合统一契约的实际区间交易量额，单位转换不等于价格复权。
3. 单位、别名、时间、状态转换只在来源适配层执行一次；类型、精度、范围不符合统一契约的候选隔离，不能由数据库隐式截断或 UI 自动修正。
4. 上线前取得交易时段边界样本，验证区间、时间标签、交易日期和实际覆盖。未验证的源时间只保存为 `source_bar_time` 证据；不得用于标准事实键、聚合或 SEALED coverage。
5. 验证后按固定时段契约生成 `trade_date/bar_start_at/bar_end_at/bar_label_at`。coverage 的 `trade_date` 是日历给出的目标日；分区使用已验证的标准交易日，不直接使用供应商时间戳。
6. 停牌、无成交与缺失分别记录；零量、空表和下载成功都不能单独证明合法空槽。

### 2.5 基础行情完成与日终封存

时间标签正确不代表行情已经完成。来源契约必须固定交易所时区、适用交易时段、集合竞价与盘后范围、上游完成证据、收盘后等待和复核间隔。具体渠道的收盘延迟资料放在其接入规范中。

- 全日日线覆盖该品类全部适用且登记的时段。若另设排除盘后等口径，须登记独立时段契约并验证返回范围，不与全日事实混用。
- 正式封存须同时满足：所有纳入时段结束、获取成功、来源完成证据或已验收的延迟/重复完整读取稳定性规则通过、第 5.1 节预期单元全部闭合。仅到达收盘时刻、存在一行或收盘价不变都不够。
- 来源没有完成标记时，用真实边界样本确定最早读取时点、两次完整读取的最小间隔及 OHLCV/amount 一致性规则；不设零间隔、不只比较 close。超过重试截止为 DEGRADED。
- 分钟 bar 同样通过所属时间槽结束与到达延迟检查；盘后范围未知时不能当作完整全日。
- 封存后延后复核发现迟到或修订数据时，执行第 4.4 节，不覆盖旧事实和 coverage。

## 3. 三层数据生命周期与读取决策

### 3.1 三个独立存储域

| 生命周期 | 内容与范围 | 容量/清理责任与观测 |
| --- | --- | --- |
| 来源侧缓存（若有） | 来源下载或订阅落盘；仅登记标的、周期和范围。无本地缓存的远程源不设虚构缓存层。 | 来源运行环境负责目录、容量、下载范围、刷新与清理；观测请求、版本、完成/失败及磁盘预算。QMT 细节见其接入规范。 |
| 应用临时缓存 | 已标准化展示响应、短时分钟图和未发布候选预览，按来源/契约/快照/到期时间隔离。 | 应用负责 TTL、容量、驱逐与可丢失性；观测命中率、过期积压、获取次数及原因。 |
| PostgreSQL 持久事实 | 通过统一契约和来源校验的标准事实版本、coverage、任务、缺口及引用；正式查询仅选已发布快照。 | 数据平台负责分区、保留、归档、备份和引用检查；观测吞吐、覆盖、revision、延迟及恢复。 |

原始响应证据独立保留在受保护对象或数据库中，不以 hash 代替内容；保留期覆盖全部引用者。display_only 默认只读已有标准缓存或已准备好的来源数据；需要额外历史补充时默认 HISTORY_NOT_CACHED。无客户端缓存的来源可执行已配置预算内的直接查询，不强制先写本地缓存。外部查询、下载和补充均须遵守已登记的 `display_download_policy_id`（展示外部获取策略，沿用原标识），固定标的、范围、费用/请求/磁盘/并发预算。

展示结果无论来自哪个渠道，都只进响应/TTL，不自动触发 coverage、异动、正式榜单、回测或分钟事实晋升；正式采集可引用同一原始证据，但必须独立完成来源校验、标准化和发布流程，不能直接把展示缓存升级成事实。

### 3.2 读取与写入决策路径

```text
收到请求或采集意图
  |
  +-- 实时交易/风控证据？ -> 选择已验收实时来源 -> 订阅/快照健康检查
  |                              -> 交易/风控事件：持久真实行情证据
  |
  +-- 已登记长期数据集？ -> 固定来源策略 + 系列快照 -> 检查 PostgreSQL
  |       |                    -> 缺口：补偿任务 -> 适配器获取/刷新
  |       |                    -> 原始证据 -> 标准化/校验 -> coverage -> 原子发布
  |       +-- 命中：按精确输入清单查询
  |
  +-- display_only？ -> 标准 TTL 命中：返回
                       -> 来源已有数据 / 已配置外部查询：标准化后返回
                       -> 缺少所需历史准备：HISTORY_NOT_CACHED
                       -> 允许受控补充：适配器获取后仅写响应/TTL
                       -> 来源不可用：按展示策略选择已验收完整预览，或明确不可用
```

执行优先级固定为：**实时交易 > 当日封存 > 补偿/修订 > display_only**。来源切换不能跳过质量、版本和预热检查；优先级只约束资源领取与限流，不表示本文实现调度器。

### 3.3 基础周期、策略登记与晋升

每一个长期数据集或策略必须在登记中声明：

- 稳定的 `dataset_id`、标的范围及绑定的 `source_selection_policy_id`；
- `canonical_base_interval`；
- 指标的“周期 + bar 数”，例如 `MA20@1d` 与 `MA20@5m` 是不同指标；
- 最早回放日期；
- 实时运行缓冲保留期；
- 归档/训练保留期；
- 删除前必须满足的引用、归档和复现校验条件。

选择规则如下：

| 需求 | `canonical_base_interval` | 长期写入规则 |
| --- | --- | --- |
| 需要 `1m` 特征 | `1m` | 仅该策略池的完整 `1m` 基础 bar 可晋升。 |
| 只需要 `5m`、`15m`、`30m`、`60m` | `5m` | 保存 `5m`；高阶分钟由它派生。 |
| 日、周、月趋势 | `1d` | 保存日线；周/月从受 coverage 约束的日线派生。 |
| 单次展示 | 无 | 可按所选来源能力请求所需周期，但只写响应或 TTL 缓存。 |

“最近 3 个完整月”只可作为实时运行缓冲的初始默认值，绝不是回测、训练或长期复盘保留期。后者由登记的最早回放日期和归档保留期决定。

### 3.4 派生周期契约

每个派生周期必须绑定不可变的 `derivation_contract_version`，至少规定：交易所时区、交易日历版本、交易时段模板、午休与集合竞价是否纳入、时间标签（起点/终点）、OHLCVA 聚合、`prev_close`、停牌状态、继承的前复权方法与快照、缺失基础 bar 和不完整桶的处理。

- `open` 为桶内首个有效基础 bar 的 `open`，`high` / `low` 为极值，`close` 为末个有效基础 bar 的 `close`，`volume` / `amount` 为求和；没有可接受的基础 bar 时不得伪造 OHLCVA。经第 5.1 节认可的 `SUSPENDED`/`NO_TRADE` 是已解释的空槽，不参与数值聚合；整桶为空时只返回状态，不能计为指标所需的有效 bar。
- `prev_close` 不做“上一根恰好可见 bar”猜测；其来源/计算必须由契约规定。派生值继承同方法/快照的基础前复权值，不得应用第二次复权。`trading_status` 只能来自被认可的基础状态证据或派生规则，不得由零量或空行推断。
- 预期时间槽缺少基础 bar 且无认可的空槽证据、午休边界不符合模板、或当前日/周/月尚未结束，均使派生条目 `completeness != COMPLETE` 或 `is_final=false`。
- 正式周/月只有在所绑定系列快照内**每个预期交易日**均满足 coverage 契约时才可 `is_final=true`。任何日为 `DEGRADED`、缺失、来源/契约不兼容或同一标的复权快照不一致时，禁止将剩余日线聚成正式周/月；至多返回附 coverage 状态的预览。派生结果固定输入清单，基础事实修订后生成新结果版本，旧结果保留其原输入。

## 4. 来源、事实和外部依赖契约

### 4.1 来源身份与物理共表边界

标准事实可以物理共表，但逻辑系列按来源和版本隔离。字段与类型遵守统一契约，原始值只能在证据层保留原单位。每根事实必须可解析：

- `source_id`：登记的具体供数通道；`upstream_source_id`：已知真实上游或 UNKNOWN，不能把采集库名称当作独立上游证据；
- `adapter_id/version`、`source_contract_version`：供数入口、字段映射、单位转换、时间及完成证据；
- `data_contract_version`：系统标准字段、类型、单位和语义，不再同时承担 SDK 参数定义；
- `source_selection_policy_id`：数据集不可变选择策略；首期每个 K 线系列固定一个已验收主来源，替代来源通过新版本发布切换；
- `ingestion_run_id`、接收时间、可读取原始证据引用和 hash；
- 标准交易日/区间/标签、基础周期、时段契约、标准 OHLCVA、bar revision、复权方法与快照。

例如聚合库属于 adapter，仍需记录实际供数通道和已知上游；两个库共用同一上游不构成独立容灾。原始对象删除前检查事实、coverage、交易快照和历史复现保留义务。

来源未经能力与映射验收只可保留原始样本；已通过标准化但未获正式选择的来源可作标准候选或展示预览。跨源比较输出明确质量报告，不自动合成一条混源 K 线。各来源的准入门槛相同，不再按“QMT/第三方”决定能否成为长期来源。

### 4.2 逻辑表与阶段边界（非 DDL）

| 阶段 | 逻辑对象 | 逻辑键、唯一性与保留/清理责任 |
| --- | --- | --- |
| 首期必需 | `kline_bar_1d` | 来源独立的标准前复权 `1d` 基础事实。唯一候选键含 `instrument_id + trade_date + bar_start_at + bar_end_at + canonical_base_interval + session_contract_id + source_id + source_contract_version + data_contract_version + adjustment_method_id + adjustment_snapshot_id + bar_revision`；每行绑定复权快照，版本不可覆盖，查询经 coverage 输入清单选择精确版本。仅在 `1d` 时间标签验证通过后按映射出的交易日年分区，长期保存；数据平台在引用/归档检查后才能删除分区。 |
| 首期必需 | `kline_ingestion_run` | 一次下载/读取/校验批次，含范围、来源/适配版本、来源缓存（若有）观测、原始证据引用、计数、状态和错误摘要。不可覆写审计字段，长期保存。 |
| 首期必需 | `kline_sync_task` | 任务唯一键见第 5 节；持有租约所有者、截止时间、单调递增的 fencing token、优先级与重试信息。完成/取消记录按审计保留策略清理，不能早于关联 `run`。 |
| 首期必需 | `kline_coverage` | `trade_date + canonical_base_interval + universe_snapshot_id + source_id + source_contract_version + data_contract_version + session_contract_id + adjustment_method_id + coverage_revision` 唯一；保存预期/实际/例外计数、`quality_status`、完成证据和 `coverage_manifest_id`。终态质量及输入清单不可覆盖；替代关系单独记录。长期保存。 |
| 首期必需 | 复权快照与输入清单 | `adjustment_snapshot_id` 固定第 4.4 节的复权证据；`coverage_manifest_id` 固定某个完整 coverage 键对应的精确事实版本和例外证据；`series_snapshot_id` 固定数据集跨日期使用的 coverage 清单。可保存为受保护的不可变对象或数据库清单，未变化部分可复用已有引用，不要求创建逐槽审计表。保留期覆盖全部引用者。 |
| 首期必需 | 当前快照指针与发布记录 | 以数据集和 source policy 为作用域，唯一选择当前 `series_snapshot_id`；指针更新及具有唯一事件 ID 的待发布记录与发布事务一起提交。第 5.2 节规定失败重放、去重及旧版本隔离。 |
| 首期必需 | `kline_gap` | `coverage` revision 下的标的/区间/缺失分类/尝试序号唯一；成功补洞也保留闭合记录。 |
| 首期必需 | `kline_cache` | 只存标准化临时展示：身份键含标的、请求周期/区间、source_id、系统/来源契约、时段、复权方法/快照和系列版本（若有）；实时未完成预览另带采集批次/更新序号，不能冒充固定系列。expires_at 为独立过期属性并建清理索引。可用 UNLOGGED，由应用 TTL 清理，永不直接成为事实输入。 |
| 首期必需 | `kline_source_contract`、`source_selection_policy`、系统数据契约 | 不可变版本及批准范围；禁止更新既有语义，只能新增版本/策略。长期保存。 |
| 首期必需 | 外部依赖引用 | 证券、交易日历、股票池快照、板块成员/分类快照的不可变 ID、版本、有效时间、来源与可读证据引用。它们不是 K 线事实表，也不把财报/新闻等写入 K 线域。 |
| 仅逐标的全量封存审计 | `kline_coverage_item` | 启用前先给出“标的数 x 交易日 x revision”（分钟扩展还须乘以预期槽数）的容量预算；按交易日月分区，保留期、冷归档位置和 revision 访问方式必须获批。未启用时，从必需的输入清单推导正常 `BAR_PRESENT`，只额外持久化 `SUSPENDED`、`NO_TRADE`、失败及范围缺失等例外；不得因此省略版本绑定。 |
| 第一个盘中策略池 | `kline_bar_minute` | 仅登记的数据集，逻辑键与日线一致但 `canonical_base_interval` 为 `1m` 或 `5m`；按已验证 `trade_date` 月分区。按各策略登记的运行/归档保留期清理。 |
| 实际交易/风控链路 | `trade_market_snapshot` | 以交易决策/订单事件 ID 唯一；长期保存真实可读取的行情窗口与决策证据，不是全市场 Tick 表。 |

分区删除不是单纯 TTL：持久事实或审计分区在删除前必须通过依赖引用、当前 coverage、榜单/回测可复现性、对象证据归档和备份恢复检查。`UNLOGGED` 缓存可因故障丢失，不得与来源客户端磁盘缓存混为一谈。

### 4.3 契约升级与历史系列

系统字段、单位、类型和业务语义变化新建 `data_contract_version`；来源映射、参数或采集证据变化新建 `source_contract_version`，价格方法/时段变化分别升级对应配置，兼容关系须有验收证据，不得就地重写历史。`none -> front` 是不兼容变化：默认长期 policy 改为前复权后，旧不复权事实继续隔离，只能以显式历史 policy 查询，不能成为默认图表/研究/榜单输入。

按生效日期维护的 **series policy/version set 是版本路由表，不是允许拼接不同语义数据的规则**。新版本只对登记的生效范围生效；历史复现显式固定原 policy 与 `series_snapshot_id`。连续图表、指标和回测请求必须在同一可兼容系列中取得完整区间及预热窗口：

- 默认连续查询跨越不兼容契约时返回 `INCOMPATIBLE_SERIES_VERSION`，附边界和各段版本；默认 policy 的历史区间尚未重建时返回 `COVERAGE_UNAVAILABLE`，不能自动回退到旧不复权段，也不能悄悄缩短 MA20 等计算窗口。
- 调用方显式请求历史分段预览时，可分别返回各段及其 policy/contract，但标记 `continuous=false`；前端不连接跨段曲线，研究/回测不跨段聚合。兼容升级只有在不可变版本路由中记录已验收的兼容关系、证明单位/时间/填充语义一致且复权快照可复用后才允许连续读取；`none -> front` 不属于兼容关系。
- 只有明确批准“从已验收来源按目标复权方法完整获取、校验、新 coverage 全部封存后切换”的迁移，才能把全历史选择策略切到前复权。单纯升级版本不自动触发全历史重算；第 4.4 节针对同一方法与来源下真实除权或数据修订的必要刷新另行执行。

### 4.4 前复权快照与已封存历史修订

`data_contract_version` 固定处理语义，不能代替某次复权数据的版本。前复权系列可能随后续公司行动和供应商修订改变。相同数据契约与方法不保证不同采集时点同一基准；保留原始响应只能证明当时取得什么，还须固定复权证据。具体来源的证据入口见对应接入规范。

1. 每个标的的 `adjustment_snapshot_id` 固定来源、契约、采集/核验时间、已验证的复权基准与作用范围、来源除权数据快照或经验证的等效版本证据，以及可读对象引用和 hash。因子快照用于识别变化与解释响应，不用于应用侧二次复权。相同证据可复用 ID，不能仅按采集日期或 `front` 字符串判定相同基准；无法验证时不能晋升。
2. 日终采集和停机恢复须检查除权证据变化；收盘后复核、供应商修订通知及登记的历史抽查也可触发修订。检查频率、最大未核验时长和回读预算由数据集登记；超过最大未核验时长仍无法完成检查时，按待修订处理并注明原因为核验不可用，不能宣称当前快照已验证为最新。修订不能仅依赖“未封存日期”扫描：即使全部日期已 `SEALED`，仍须检查已持久化系列。
3. 先登记本次修订原因与受影响标的、基础周期、日期范围和依赖者。除权基准变化须覆盖该标的仍供连续查询及指标预热使用的全部受影响历史；无法可靠界定时，按登记的完整保留区间回读。所有正在使用的基础周期分别验收。必须从该系列选定来源刷新/重读，不能只向本地缓存末尾追加，不能用应用比例换算；读取前后核验复权证据一致，期间变化则废弃候选并重新采集。
4. 重读生成新的 bar 版本、coverage revision 和不可变系列快照。同一标的参与一次连续计算的全部 bar 必须属于同一已验证复权快照；不同标的可有不同快照。新 `series_snapshot_id` 明确引用每个日期的完整 coverage 键及输入清单，未受影响的输入可以复用。范围内需要替换的 coverage 全部 `SEALED` 后，才按第 5.2 节原子切换当前系列快照。
5. 修订进行中或失败时保留旧快照，返回其原 `as_of` 和 `REVISION_PENDING`；要求最新一致序列的请求返回 `DATA_REVISION_PENDING`。新取得数据仅可作候选或带状态预览，不能与旧快照拼接。旧快照按原输入继续可复现；周/月、指标和榜单的最新结果须随新输入生成新版本。
6. 单次请求或研究任务开始时固定 `series_snapshot_id`，分页、跨日期和预热读取共用该快照，不能每次查询分别取最新 revision。历史结果复现固定原快照；声称模拟“当时已知信息”的回测还须限定证据可用时间，不能把今天回读的修订历史标成当时可见的数据。

### 4.5 多源比较与系列切换

不同类型数据可以分别选源，例如行情 A、股本 B、成员 C；它们通过证券 ID、有效时间、可得时间和输入清单关联，不混入同一 K 线事实表。各来源 coverage 独立计算，跨数据集任务固定全部依赖快照；不能用另一来源的计数补高当前来源完整率。

同类 K 线并存时先按统一契约标准化，再验证证券、区间、时段、复权方法和数量口径可比。按选择策略登记的字段容差比较；超差候选进入冲突处理，不按先返回、平均值或数量相加自动定事实。

更换主来源须登记新策略，取得目标连续范围及指标初始化/预热所需历史，完成全部来源验收、coverage 和下游重算后原子发布新系列。旧结果保留原快照；新源短缺或失败时保留旧 as_of/状态或明确不可用，不能静默缩短窗口。跨源逐 bar 补洞与逐字段拼接后置，不在本期自动开启。

来源更换不改变标准数据库字段/值类型、服务字段名/单位或 UI 展示公式。完整能力与异常规则见统一契约第 6 节。

## 5. 补偿、coverage 与并发状态机

四个实体分别表达不同状态，禁止混用。

| 实体 | 负责的问题 | 状态 |
| --- | --- | --- |
| `kline_sync_task` | 某个可领取工作是否可执行 | `QUEUED -> LEASED -> RUNNING -> SUCCEEDED`；失败可转 `RETRY_WAIT` 后重回 `QUEUED`，或转 `FAILED`/`CANCELLED`。依赖/权限/容量未满足时为 `BLOCKED`。`BLOCKED` 只属于任务。 |
| `kline_ingestion_run` | 一次实际下载、读取、标准化和校验批次 | `STARTED -> READING -> VALIDATING -> COMMITTED`，或 `FAILED` / `ABANDONED`。一个任务可有多个 run。 |
| `kline_coverage` | 一个交易日、范围和契约版本是否足以供正式消费 | `quality_status` 为 `PENDING -> BUILDING -> SEALED`，或 `PENDING/BUILDING -> DEGRADED`。终态质量和输入不变；`SUPERSEDED` 仅表示指定发布作用域内的替代关系，不是质量状态。不存在 `BLOCKED` coverage。 |
| `kline_gap` | 一个明确缺口及其处理结果 | `OPEN -> RETRYING -> RESOLVED`，或 `EXHAUSTED` / `WAIVED`；`WAIVED` 必须有批准理由，仅表示停止重试，仍是未满足的预期单元，不能成为 `BAR_PRESENT` 或使 coverage 封存。 |

```text
任务：       QUEUED -> LEASED -> RUNNING -> SUCCEEDED
                         |         |-> RETRY_WAIT -> QUEUED
                         |         |-> FAILED / CANCELLED
                         +-> BLOCKED --(依赖恢复后)--> QUEUED

批次：       STARTED -> READING -> VALIDATING -> COMMITTED
                                   \-> FAILED / ABANDONED

coverage 质量： PENDING -> BUILDING -> SEALED
                       \-> DEGRADED
系列选择：     snapshot N --(原子切换指针)--> snapshot N+1
旧 coverage：  原 SEALED/DEGRADED 保留，替代关系记为 SUPERSEDED
```

### 5.1 coverage、缺口与当前查询

覆盖范围由 PIT 交易日历、`universe_snapshot_id`、证券上市/退市状态、基础周期、来源、契约和交易时段共同定义，不能用“最新一条 bar”冒充完整水位。所有计数针对互斥的预期单元；修订股票池或时段须生成新的范围证据，不能在失败后缩减分母以制造完整率。

| 预期单元 | `BAR_PRESENT` 准入条件 | 认可的无 bar 情况 |
| --- | --- | --- |
| 日线：标的 x 目标交易日 | 输入清单中恰有一根通过字段、来源、契约、复权快照及第 2.5 节完成检查的日线版本 | 覆盖整个预期交易日的 `SUSPENDED` 或 `NO_TRADE` 证据；局部停牌不能豁免其他时段。 |
| 分钟：标的 x 交易日 x 预期时间槽 | 按已验证时段模板生成 `1m`/`5m` 槽位，每槽恰有一根时间边界、来源、契约、复权快照、数值和完成性均通过的 bar 版本 | 精确覆盖该槽的 `SUSPENDED` 或 `NO_TRADE` 证据；不得仅因当日日线存在就视为分钟完整。 |

- 午休及不在登记口径内的时段不生成预期槽。重复时间戳、错位或跨越时段边界的 bar 不满足槽位；零成交量或 OHLC 为空也不自动成为有效 bar。必需价格/量额字段的可用性按品类契约校验。已认定整槽停牌的响应保留为例外证据，不再计入 `BAR_PRESENT` 或参与数值聚合，避免重复计数。
- 正常数据统一命名为 `BAR_PRESENT`；确认应有但尚无可接受 bar 的缺口命名为 `MISSING_BAR`。其他缺口原因至少包括 `NOT_DOWNLOADED`、`LOCAL_RANGE_MISSING`、`DOWNLOAD_ERROR`、`UPSTREAM_ERROR`、`INVALID_BAR`。原因无法区分时记录 `UNKNOWN_MISSING` 及现有证据，不能猜测；`SUSPENDED`/`NO_TRADE` 是有证据的覆盖例外，不与抓取错误混称。
- 只有来源契约认可、已映射为标准状态且覆盖目标区间的证券状态证据，才能认可 `SUSPENDED`。`NO_TRADE` 必须有契约认可的完整区间证据，例如已验证覆盖整个槽位的交易记录或状态源；空响应、零量、超时、未下载或下载成功本身均不是充分证据。尚无可靠证据源的无 bar 单元保持缺口，不能伪造价格。
- `SEALED` 要求 `expected_count = bar_present_count + suspended_count + no_trade_count`，且每个预期单元只计一次、未解决/耗尽/豁免缺口数为零，并通过第 2.5 节完成检查。合法空槽允许 coverage 封存，但不产生可成交 bar。`WAIVED` 只能停止重试，coverage 仍为 `DEGRADED`；有效范围为空时记录其范围证据，不能伪造任何行情。
- 每个 coverage 终态必须绑定不可变的 `coverage_manifest_id`，列明每个正常单元的完整事实键和 `bar_revision`、复权快照，以及所有例外的区间、分类和证据。必须固定交易日历/时段/股票池版本与计数。可采用可读的分片或压缩清单，不能只存总数或 hash；未启用 `coverage_item` 时也必须能从清单唯一重建输入，禁止按每根 bar 的“当前/最大 revision”回查历史。
- 对 `DEGRADED` 补洞或对 `SEALED` 修订均创建下一 `coverage_revision`，重新计算完整范围和终态，不能只保存本次新增的 bar。原质量和清单保持不变；重试处理结果可以追加，但不得反向改变旧 coverage 的计数、例外或质量结论。旧版本是否被替代从指定数据集/source policy 的系列选择关系得出。
- 当前查询先固定当前 `series_snapshot_id`，再读取其中明确绑定的 coverage。`SEALED` 返回正式事实；`DEGRADED` 只返回带状态、缺口与版本的可用预览，正式榜单/默认回测不可使用。若新修订未就绪，按第 4.4 节返回旧快照及待修订状态；没有适用快照时返回 `COVERAGE_UNAVAILABLE`，不得把其他日期当作目标日数据。后台任务 `BLOCKED` 不改变既有 coverage 的质量，也不能使未完成候选成为当前。

### 5.2 幂等、租约与事务边界

`kline_sync_task` 的任务唯一键为：

```text
task_kind + source_id + source_contract_version + canonical_base_interval + trade_date
+ universe_snapshot_id + data_contract_version + session_contract_id
+ adjustment_method_id + coverage_revision
```

上述键适用于按交易日工作的采集/修订任务。多日修订的最终发布任务使用 `publish_series + dataset_id + source_selection_policy_id + series_snapshot_id` 唯一键，关联全部候选 coverage；它只发布已完成的输入，不再次下载行情，同样遵守租约与 fencing 校验。

同一补洞/修订意图须在创建任务时原子分配或复用其目标 `coverage_revision`；终态前的重复投递和租约接管复用该版本，不能为每次重试分配新 revision 来绕过唯一键。已提交终态的任务重复投递只确认已有结果；终态后的新一轮补洞、数据修订或范围变化则建立新意图及版本。

worker 以带过期时间的租约领取任务（例如行锁/`SKIP LOCKED`）；领取时保存所有者、数据库时钟确定的截止时间及单调递增的 `fencing_token`。续租须匹配当前所有者/token；到期或释放后才可接管，接管增加 token。run、coverage 终态提交及当前快照切换必须在事务内锁定并校验任务 token、未过期租约和可提交状态，校验与提交之间不允许另一个 worker 完成接管。旧 worker 恢复后只能保留失败/`ABANDONED` 证据，不能提交正式结果。行锁领取与唯一任务键本身不能替代此校验。

持久化、选择与发布的边界固定如下：

1. 下载/读取前先保存 run 起始记录。正式事务前持久化可读原始证据、不可变输入清单与事实候选；失败候选不可被正式查询选中，按无引用对象保留策略清理。原始证据须先通过可读性与完整性校验。
2. 在数据库提交单元内校验租约、候选输入、目标 coverage 尚未终结及适用的预期父快照，然后写入事实版本的有效引用、run/任务结果、缺口和 coverage 计数/终态。同一任务及输入已提交时返回已有结果；相同版本已存在但输入 hash 不同必须报冲突，不能覆盖。任务结果、run 及 revision 不得出现提交一部分的情况。
3. 普通单日发布在同一提交单元内创建系列快照、以比较并交换方式更新作用域唯一的当前快照指针、记录替代关系，并写入具有唯一 `event_id` 的待发布记录（transactional outbox 或同等持久机制）。竞争者若已改变父快照，本次不得覆盖其指针，须基于新父快照重新校验候选系列。
4. 多日历史修订可先分别提交各日候选 coverage，保持旧当前快照不变；全部受影响范围封存后，由持有有效租约的最终发布任务在一个数据库事务内完成范围完整性校验、新系列快照登记、当前指针切换及 outbox 写入。尚未被已发布快照引用的 `SEALED` 候选不属于默认查询输入。
5. 数据库提交后只执行外部事件投递，不再依赖进程内存补写权威当前指针。投递器扫描持久待发布记录并失败重放；交付语义为至少一次，消费者在其业务提交边界按 `event_id` 去重。事件携带作用域、父/新快照 ID 和发布序号，乱序或重复事件不得回退下游当前版本。
6. 必须验证“证据已保存但数据库回滚”“数据库已提交但尚未投递”“已投递但确认丢失”均可恢复。失败 run 在独立审计提交中记录错误；进程崩溃留下的未完成 run 在恢复时标记 `ABANDONED`。不得出现已发布快照引用未提交事实、不可读证据或半段修订历史的状态。

### 5.3 停机补偿

1. 固定当前 source policy 与系列快照，从其中连续 `SEALED` 水位（而非最大日期或尚未发布的候选 coverage）和 `bootstrap_start_date` 计算缺口范围。首次无水位时，起点、最早回放日期和股票池快照必须是显式登记值；不兼容契约的水位分别计算。
2. 用 PIT 交易日历生成未封存的实际交易日；按日期由旧到新建独立、幂等任务。周末/节假日不应制造假缺口。
3. 根据来源能力和记录区分是否有本地缓存、范围是否覆盖、请求/下载是否失败、上游是否失败，再写相应 gap 分类；不能用空 DataFrame 一次判断全部原因。证据不足时保留 `UNKNOWN_MISSING`，补充诊断后再分类。
4. 日终封存、缺口重试和供应商修订各产生可追踪 run；重试耗尽时 coverage 为 `DEGRADED`，不是 `SEALED`。
5. 补偿限流不得抢占实时交易和当日封存所需的来源连接/订阅配额。
6. 独立检查除权/供应商修订及未完成发布记录；连续封存水位只回答缺口问题，不能跳过第 4.4 节已封存历史的修订检查，也不能替代 outbox 重放。

## 6. 趋势、榜单与 PIT 依赖

### 6.1 趋势计算

趋势策略覆盖分钟、日、周、月。任何 MA/EMA 等指标必须引用已登记的 `(series policy, canonical_base_interval, derived interval, bar_count, derivation_contract_version)`，每次计算再固定 `series_snapshot_id` 和实际输入清单；例如 `MA20@1d`、`MA20@5m`、`MA20@1w` 不是同一指标。`SUSPENDED`/`NO_TRADE` 不伪造有效 bar，预热不足须返回明确状态；跨契约或复权快照的连续计算遵守第 4.3、4.4 节。策略不得因图表请求或临时缓存而获得未覆盖的基础序列。

### 6.2 四类检测与榜单场景的边界

| 场景 | 数据状态 | 结果规则 |
| --- | --- | --- |
| 日终全市场异动检测 | 当前日 `SEALED` 日线 coverage | 只处理正式日线；缺口/降级直接阻断或显示不完整。 |
| 日终正式涨幅榜 | 当前日 `SEALED`，且所有 PIT 依赖可读 | 持久/可复算结果，必须保存完整输入清单。 |
| 板块内个股趋势和领涨股 | 目标日/周期的可用 coverage + PIT 板块成员 | 依赖当时板块成员与分类，不从当前成员表回推历史。 |
| 盘中预览榜单 | 实时/未完成数据，`is_final=false` | 单独命名为预览；不得与日终正式榜单混称或替代。 |

每一份日终正式榜单必须绑定并可读回：

- `universe_snapshot_id`；
- `sector_membership_snapshot_id`；
- 分类体系、版本和 `as_of_date`；
- `series_snapshot_id`、完整日线 coverage 键（含 `coverage_revision`）、`coverage_manifest_id` 及逐标的复权快照引用；
- `source_selection_policy_id`；
- 涨幅计算口径（如同快照前复权 close 相对 prev_close，或独立的市场涨跌参考口径）；
- 排名时间点；
- 纳入/排除规则及其证据：新股、ST、停牌、退市、无成交、流动性过滤。

同一份榜单的筛选、涨幅计算和排序固定同一输入快照。历史数据修订后，旧榜单保持原快照可复算，最新口径榜单另生成版本；未重算的结果必须标识其输入版本，不能与修订后的最新结果混称。

证券主数据、交易日历、上市/退市状态、股票池快照、板块成员和行业分类历史是外部不可变 PIT 依赖契约，不进入 K 线事实表。尤其不得假设任何来源的当前板块名单等价于历史某日的板块成员；历史榜单必须引用该日可读取的成员快照。

## 7. 实时交易行情安全契约

实时流仅服务已批准的小交易标的集合。每个订阅必须记录订阅范围/订阅号、来源与契约、订阅健康状态、来源最后行情时间、应用接收时间、心跳结果、断线/重连次数、最大可接受陈旧度和当前未知时间窗口。

1. 无心跳、回调停止、接收时间超过陈旧度、来源时间倒退/不可解析、或断线期间无法确定是否遗漏行情时，创建未知窗口并将关键标的置为 `STALE_DATA`。
2. `STALE_DATA` 下禁止新开仓；已有订单处置和风控动作仍须记录，但不得把“没有新 Tick”当成“行情稳定”。
3. 恢复条件是重连成功、订阅健康恢复、未知窗口以历史补洞或明确不可补的状态处理、窗口数据与当前契约验证通过；仅收到一条新行情不足以解除。
4. 交易、撤单、风控拒绝和最终回报必须写 `trade_market_snapshot`。快照保存真实可读取的 Tick/分钟窗口（或受保留策略保护的不可变对象引用）、来源契约、订阅健康/陈旧状态、策略和参数版本、信号、风控决定、订单请求和最终回报。hash 可附带校验，但不能取代可读取行情证据。

## 8. 容量、权限、保留与验收

### 8.1 上线前来源能力预检

对每个来源分别记录并验收：

- 具体 source_id、已知上游、入口/适配/来源契约版本，及其实现的系统契约版本；
- 品类、历史/实时、基础与派生周期、最早日期、退市覆盖、权限、延迟、限流和修订刷新能力；
- 实际字段、原始单位、转换倍率、目标精度、未知枚举、缺失/空值和合法空槽证据；
- 证券映射、交易时段边界、集合竞价/盘后、时间标签和行情完成判据；
- 跨除权事件的算法、锚定、量额处理及因子/等效版本证据；
- 有客户端缓存时的目录、占用、容量、准备范围和清理责任；远程请求的费用/配额预算；
- 所需历史股本、板块成员、日历等依赖的有效时间、可得时间及实际覆盖；
- 标准入库/读取/服务数值投影与既有 UI 换算，和真实系列切换能力。

QMT 专属检查见接入规范；其他来源须提供同等内容的来源契约。接口文档存在不等于真实权限或历史能力通过。

### 8.2 PostgreSQL 压测与数据保留验收

在真实股票池、真实写入批量和预期并发下量化：日线/分钟写入吞吐、索引体积、单标的图表查询、横截面日终查询、固定快照的 coverage revision 查询、原始证据/输入清单读取、系列快照切换事务、outbox 积压与重放、备份和恢复时间。必需清单和复权修订的容量计入首期预算，不得以 `coverage_item` 未启用为由省略。只有容量预算和压测结论支持，才能启用分钟事实或 `coverage_item`，不能因“可能将来需要”提前建全量审计表。

分区删除前必须执行：引用检查、榜单/回测/交易快照可复现性检查、原始证据归档检查、备份恢复演练和删除责任审批。应用 TTL 清理只处理 `kline_cache`，不能声称释放了来源侧缓存或 PostgreSQL 事实分区。

### 8.3 验收清单

- [ ] 各来源先映射/换算再入库：volume 手、amount 元、比例小数；数值类型、精度、空值和 UI 输入映射通过统一契约 C01～C12。
- [ ] 原始响应可读取，原单位/时间/字段保留；原始证据、标准候选与已发布数据可区分。
- [ ] 数据契约、来源契约、适配版本、复权方法/快照、时段契约和来源选择策略分别绑定，不用一个版本掩盖不同变化。
- [ ] 历史/实时和原生/派生能力已实测；未知源时间不能形成正式键或 coverage。
- [ ] 时间标签验证与行情完成验证分开；迟到、盘后范围未知或仅有一行日线不会提前封存。
- [ ] 分钟完整性按标的和时间槽检查；缺槽、重复槽、错位槽不能通过，午休不生成假缺口，局部停牌不豁免整日。
- [ ] BAR_PRESENT、MISSING_BAR、合法空槽和抓取失败不混用；WAIVED 不提高完整率，符合封存等式。
- [ ] 来源缓存（若有）、TTL 和持久事实各自有预算及清理责任；展示请求不触发事实晋升。
- [ ] 停机数日按连续封存水位和交易日历补偿；任务、run、coverage 和 gap 状态独立。
- [ ] 补洞 DEGRADED 与修订 SEALED 都生成新 revision，旧质量和输入保持可复现。
- [ ] 已封存历史发生除权或供应商修订仍触发回读；期间因子改变或失败不发布混合基准。
- [ ] 查询分页、跨日期、指标初始化/预热固定系列快照，修订后生成新结果，旧结果仍可复现。
- [ ] 不兼容单位/价格方法/时段/来源切换不按日期拼接；历史不足不回退旧口径或缩短窗口。
- [ ] 来源并存比较按固定容差，冲突不自动平均；跨数据集依赖固定各自来源与 PIT 版本。
- [ ] 新来源完整验收和历史重建完成前不替换正式系列；失败保留旧 as_of/状态或明确不可用。
- [ ] worker A 租约过期、B 接管后 A 不能提交；重复投递复用 revision，竞争发布不覆盖新父快照。
- [ ] 数据库回滚、提交后未投递、投递后确认丢失均能恢复；outbox 重放、去重和乱序隔离有效。
- [ ] 正式周/月只由完整日线形成，盘中预览与日终正式榜单有明确状态。
- [ ] 交易订阅断线/未知窗口进入 STALE_DATA，真实交易行情证据可读回；行情替换不冒充交易通道替换。
- [ ] UI 的 11 行、颜色、精度、小额阈值、万手/亿、时间、hover、图例、坐标轴及指标行为没有因来源变化而改变。

## 9. 已固定与待数据集登记的边界

本文已固定：来源无关的统一字段/类型/单位；UI 表现不变；默认前复权研究系列、不伪造填充；首期全市场日线；分钟、coverage item、交易快照按需求启用；最近 3 个完整月仅为运行缓冲默认值。版本清单、历史修订、租约校验和原子发布继续是必需规则。QMT 不再是唯一长期来源，其他来源也不能未经验收直接晋升。

1. 所选主来源、候选来源、实际能力、逐字段比较容差、冲突处理、切换范围与来源策略版本。
2. 展示外部获取策略、允许入口、最大历史范围和来源请求/费用/磁盘/并发预算。

4. 涨幅公式、分类体系、PIT 快照来源、ST/新股/停牌/退市/无成交/流动性过滤。
5. 实时陈旧度、心跳、未知窗口及恢复条件；交易通道能力另行登记。

8. 时段、价格方法、来源完成/刷新判据、历史修订检查频率、最大未核验时长、回读预算与合法空槽证据。资源不足时明确待修订，不继续拼接。
