# Kratos 风格代码评审清单

## 1. 分层职责
- `server` 层是否只负责创建服务、注册协议服务与配置中间件。
- `service` 层是否只做协议适配、参数校验、错误映射与上下文适配，不直接写 SQL/HTTP 第三方调用。
- `usecase` 是否承载核心业务流程与规则。
- `data` 层是否只做基础设施实现与适配。

## 2. 契约优先
- 接口变更是否先改 proto 或 port，再改实现。
- handler/service/usecase 的输入输出是否通过清晰 DTO/command 传递。
- 是否避免“未定义契约先编码”的临时实现。

## 3. 可替换性
- 外部依赖是否通过 port 抽象接入。
- 是否可在不改 usecase 的情况下替换数据源/存储实现。
- 是否出现跨层直接依赖具体实现（如 usecase 直接 import repo 实现）。

## 4. 可观测性
- 关键路径是否保留 trace_id 或请求上下文。
- 错误日志是否包含必要上下文且不泄露敏感信息。
- 错误是否统一包装并映射到协议层。

## 5. 工程一致性
- 新增模块目录是否对齐 `internal/modules/<module>/` 约定。
- 是否补齐基本测试（至少 smoke/单测）。
- proto 变更后是否执行并提交 `make proto` 生成物。
