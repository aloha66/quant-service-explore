# QMT 来源接入规范：能力、原始字段与统一契约映射

> 状态：2026-09-12 从原存储策略和显示文档中拆出的来源规范。QMT 是候选来源之一，不是系统唯一长期来源；真实目标客户端尚待验收。
>
> 上位契约：[统一行情数据契约](2026-09-12-market-data-contract.md)。本稿只规定 QMT 如何输出标准数据，不拥有 UI 展示规则、数据库单位或通用采集流程。

## 1. 入口、身份与能力登记

QMT 的每个接入通道登记 `source_id`、已知真实上游或 UNKNOWN、`adapter_id/version`、`source_contract_version`、所实现的 `data_contract_version=market-data/v1`、客户端/Python 包版本和权限。原 `data_contract_version` 中的 QMT API 细节归入来源契约，迁移时保留旧版本到新版本的明确对应关系。

`source_contract_version` 必须固定 `api_family`：内置 `ContextInfo` 或原生 `xtquant.xtdata`，以及完整调用入口、参数、返回形态和已验收范围。两个家族的同名函数不能互换。未选定家族或预检未通过时只能保留受控原始样本。

| 能力 | QMT 接入规则 |
| --- | --- |
| 历史链路 | `download_history_data -> QMT 客户端本地历史 -> get_market_data_ex / get_local_data`；已有范围可直接读取。 |
| 下载与修订 | 原生下载入口列有 `incrementally`，内置部分客户端不支持；按家族/版本验证。增量下载成功不等于旧历史已刷新。 |
| 本地读取 | 内置 `ContextInfo.get_local_data` 被标记为不推荐；不能把该说明套给原生 `xtdata.get_local_data`。原生本地入口有 `fill_data`、`data_dir`，须显式控制。 |
| 历史与实时 | 内置 `ContextInfo.get_market_data_ex` 支持 `subscribe=False`；原生 `xtdata.get_market_data_ex` 无该参数，实时另行订阅。不得向原生误传该参数。 |
| 响应完成边界 | 历史与订阅实时可能同时被读取；采集须指定闭合范围并校验完成状态，未调用订阅不能证明返回只含历史。 |
| 空响应 | 不能单凭空表推定停牌、无成交、未下载或上游无数据；结合下载记录、缓存覆盖和认可状态证据分类。 |

官方入口：[内置行情函数](https://dict.thinktrader.net/innerApi/data_function.html)、[原生 XtData](https://dict.thinktrader.net/nativeApi/xtdata.html)、[股票数据说明](https://dict.thinktrader.net/dictionary/stock.html)。它们是接口资料，不替代本客户端实测。

## 2. QMT 基础周期与读取规划

QMT 历史链路的基础周期为 `tick/1m/5m/1d`；获取其合成历史前先准备相应基础历史。下表是 QMT 路径，不约束其他来源或系统自行按已登记规则聚合的能力。

| 标准目标周期 | QMT 历史基础 | 接入说明 |
| --- | --- | --- |
| Tick | `tick` | 独立实时/快照契约，不构建全市场长期 Tick 仓。 |
| `1m/3m` | `1m` | `3m` 为派生，校验区间与完成性。 |
| `5m/10m/15m/30m/60m` | `5m` | QMT 合成历史按其基础准备；接口可能使用 `1h` 等标签，按入口映射到标准 `60m`。 |
| `1d/1w/1mon` | `1d` | 周/月继承已验证日线输入与复权快照，不再次复权。 |

原生周期、请求周期和数据集 `canonical_base_interval` 分别记录。若数据集登记以 `1m` 聚合 `5m`，按系统派生契约执行并记录输入，不能把它伪称为 QMT 原生 `5m`。实时可订阅合成周期不证明所需历史已下载。

## 3. K 线原始字段到标准字段

原始响应完整保留原键名、值、字段缺失/空值、索引及证据。标准候选必须满足统一契约；以下不能被理解为“所有字段原样透传入库”。

| QMT 原始字段 | 标准字段/证据 | 映射与校验 |
| --- | --- | --- |
| 证券代码，如 `600000.SH` | `instrument_id`，原代码留证 | 经系统证券主数据映射市场与品类，不只去掉后缀。 |
| `time` / 字符串索引 | 原始 `source_bar_time`；标准交易日、区间和标签 | 保留原值/解析规则。通过边界样本后生成 `trade_date/bar_start_at/bar_end_at/bar_label_at`；未验证时只作受控样本。 |
| `open/high/low/close` | 同名标准四价 | 本来源研究路径固定 `dividend_type='front'`；验证符合登记的复权方法后保存标准数值，不二次复权、不按展示精度舍入。 |
| `volume` | `volume`，手 | 本期股票 `1d/1m` 目标输入单位为手，验收通过后倍率为 1；其他周期和品类分别验收。实际返回若为股，须新建已验证来源映射后除以 100，不能在 UI 猜测。 |
| `amount` | `amount`，人民币元 | 验证实际单位后按来源契约倍率转换；未知单位阻止晋升，不因为字段同名就认定为元。 |
| `preClose` | 原始前收候选；合格时映射 `prev_close` | 必须验证为上一交易日同复权快照收盘基准；否则由服务读取标准上一交易日日线。市场除权参考价单独映射，不回退结算价或上一分钟。 |
| `suspendFlag` | `trading_status` + 原始枚举证据 | 内置常见 `0/1`；原生表另列 `-1` 当日起复牌。按家族验收映射 NORMAL/SUSPENDED/RESUMED，未知为 UNKNOWN，不能把 -1 当作停牌。 |
| 内置 `settle`；原生表 `settelementPrice` | 原始扩展证据；适用品类的独立结算字段 | 保留原拼写与值，固定别名映射；多个候选键冲突须隔离。股票标准 K 线不要求结算值，不用于昨收兜底。 |
| `openInterest` | 原始扩展证据；适用品类持仓量 | 不提升为股票必需字段，不以无意义的股票值污染通用业务。 |

原生表仍使用 `settelementPrice` 拼写，不能擅自把原始证据改写为正确英文。扩展字段如果将来进入业务计算，须补充品类契约、单位、类型和验收；保留原始证据不等于允许消费未标准化扩展值。

### 3.1 成交量依据与固定 UI 边界

| 官方依据 | 能证明的内容 | 证据边界 |
| --- | --- | --- |
| [XtData K 线字段表](https://dict.thinktrader.net/nativeApi/xtdata.html) | K 线有 `volume/amount`。 | 此表未逐项写明 K 线成交量单位。 |
| [股票数据字段](https://dict.thinktrader.net/dictionary/stock.html)、[版本记录](https://dict.thinktrader.net/nativeApi/download_xtquant.html) | 股票 Tick / 全推的 volume 手口径说明。 | 不能单独证明每个 K 线入口/周期的单位。 |
| [内置行情函数日线样例](https://dict.thinktrader.net/innerApi/data_function.html) | 不复权日线样例 `volume=377076`、`amount=322145532.0`、价格范围 `8.52..8.58`；按元和每手 100 股计算均价约 `8.543252`。 | 样例算术支持手口径；不是目标客户端实测，也不据此切换到不推荐的读取入口。 |

统一契约已经固定标准量为手。QMT 股票 `1d/1m` 按上表目标规则验收；客户端若不符，处理为接入版本兼容问题。**显示层始终只执行 `volume / 10000`，标准 `45400` 手始终显示 `4.54万手`。** `377076` 手对应 `37.7076` 万手，再由既有 UI 格式化。

## 4. 时间、填充与前复权

1. 研究路径固定 QMT `dividend_type='front'`。`none/back/front_ratio/back_ratio` 为独立口径，不能混入同一系列；实际交易快照独立保留不复权价格。参数只写在来源规范，系统消费者使用统一契约的价格配置。
2. 正式读取入口支持 `fill_data` 时显式 `False`，包括原生 `get_local_data`。无法关闭且不能证明未填充的入口仅能保存样本或受标识预览。无 bar 的停牌、无成交与缺失仍须用状态和覆盖证据判断。
3. 同标的跨 `1m/5m/1d` 验证 `09:30`、午休前后、`15:00` 及适用盘后边界，比较时间戳、索引和实际区间。结论登记在来源契约，并映射到固定系统时段/标签契约。
4. 验证复权算法、锚点、事件作用范围和量额是否变换。标准股票量额只允许实际交易量额及单位转换；无法提供此语义时，不能仅因 OHLC 正常就通过。
5. `adjustment_snapshot_id` 固定 QMT 除权快照或已验证等效证据、采集/核验时间、作用范围、对象引用和 hash。相同 `front` 参数不保证不同采集时点同一基准。历史刷新按存储策略第 4.4 节执行，不只追加新日期。
6. QMT 读取前后复权证据须一致。变化中得到的候选不能发布；旧快照继续可读并标注待修订。应用不通过比例换算偷偷替代上游历史刷新。

[官方复权实例](https://dict.thinktrader.net/nativeApi/code_examples.html)用于核对算法和历史变动边界；正式接入仍需目标客户端样本。

## 5. Tick、盘口与历史依赖

| 原始字段/能力 | 处理 |
| --- | --- |
| `time/stime` | 留原时间证据，验证后生成行情时间及接收时间，分别用于新鲜度判断。 |
| `lastPrice/lastClose/open/high/low` | 实际最新价、前收及当日开高低；不得与前复权研究四价合成同一系列。 |
| `volume/amount` | 映射独立 Tick 的 `cumulative_volume/cumulative_amount`；按品类统一数量/金额单位，不写入分钟区间量字段。 |
| `stockStatus` | 独立状态映射，不能自动等同 `suspendFlag`。 |
| `askPrice/askVol/bidPrice/bidVol` | 独立盘口价量，保留真实档数、单位、时点和可用性；样例五档不证明所有权限都有五档。 |
| `get_full_tick` | 最新快照能力不等于历史逐笔覆盖，不能据此声明可回测历史 Tick。 |
| `get_instrument_detail` 等元数据 | `FloatVolume` 等别名只在已验证的来源映射内转为独立历史股本数据；验证单位、生效区间和可得时间，当前值不证明完整历史。 |
| 板块、证券和日历入口 | 登记来源/分类版本、成员有效时间及可得时间；当前名单不证明历史当时名单。 |

QMT 官方说明分笔周期为不复权。Tick/盘口到标准实时契约的完整字段类型随对应能力单独验收，本稿的 K 线类型不能自动套给逐笔数据。账户、资产、持仓、委托来自交易侧，使用独立交易契约；参考 [QMT 交易模块](https://dict.thinktrader.net/nativeApi/xttrader.html)，不以行情替换证明交易通道已替换。

## 6. 本地缓存、完成与健康检查

QMT 本地缓存独立于应用 TTL 和 PostgreSQL：记录目录、磁盘配额、下载范围、基础周期、订阅可能落盘、清理责任和剩余空间。仅应用 TTL 清理不能释放 QMT 磁盘。`display_only` 未命中时默认不启动历史补充，返回 `HISTORY_NOT_CACHED`；有明确展示下载策略才在预算内下载，结果仅作标准化预览，不进入正式 coverage。

正式获取按数据集任务触发下载/刷新。限流优先级为实时交易、当日封存、补偿/修订、展示；原始下载与读取记录可区分 NOT_DOWNLOADED、LOCAL_RANGE_MISSING、DOWNLOAD_ERROR、UPSTREAM_ERROR，证据不足为 UNKNOWN_MISSING。

QMT 官方提示普通股票收盘行情可能晚于 15:00 下发；适用品种盘后定价交易需关注 15:30 后数据。[数据更新时间](https://dict.thinktrader.net/dictionary/question_answer.html)。这些时间不构成完成保证：必须验证返回时段范围、延迟和重复完整读取的稳定性，不能仅看收盘价不变。

订阅记录连接/心跳、来源最后时间、接收时间、断线未知窗口和历史补齐能力。过期或窗口未知进入 STALE_DATA，不能因其他来源偶然返回一条快照就解除；恢复遵守统一实时安全契约。

## 7. 真实接入验收清单

- [ ] 选定 API 家族、完整入口、客户端/包/适配版本及实际权限；原生未误传 `subscribe=False`。
- [ ] 历史可用范围、退市证券、基础周期、实时延迟、下载/刷新和缓存清理均有实测证据。
- [ ] 股票日线与分钟量额单位分别验证；手/股、元/千元、小数手均正确归一，并通过统一契约 C01～C06。
- [ ] 原字段缺失、null、别名冲突、`suspendFlag=-1`、未知枚举、非法值、超精度均能区分。
- [ ] 分钟边界、午休、集合竞价、盘后范围、区间量与 Tick 累计量、未完成 bar 替换均验证。
- [ ] 跨除权事件、前后采集、量额处理、证据变更中途失败、全历史刷新和快照切换均验证。
- [ ] 历史股本、成员、日历实际覆盖和可得时间按能力记录；未具备的能力不声称已支持。
- [ ] 正式数据服务保持标准字段、数值类型和单位，UI 无来源判断、双重换算或展示变化。

本次仅完成文档拆分、官方资料沿用与契约对齐；未连接 QMT 或交易端。以上勾选项必须由真实接入证据完成，不能用文档静态检查代替。
